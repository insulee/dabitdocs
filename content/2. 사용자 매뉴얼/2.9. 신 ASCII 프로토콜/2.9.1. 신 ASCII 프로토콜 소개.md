
> [!abstract] 신형 컨트롤러(DIBD520·720 계열)의 확장 ASCII 프로토콜 — 명령 구조·응답 규칙·지원 버전을 안내합니다
> 기본 패킷 프레임은 [[2.8.1. ASCII 프로토콜 매뉴얼]]과 동일하며, 이 장은 신형 펌웨어에서 추가된 명령 체계만 다룹니다.

## 1. 지원 대상

- **컨트롤러**: 특정 기종 전용이 아니라 **펌웨어 기준**입니다 — DIBD500·600·520·720 계열 모두 지원 (V4.1.3 기준 DIBD500S·600T·720U 실기 확인)
- **펌웨어**: **V3.6.0 이상**부터 단계적으로 지원 — 명령별 요구 버전이 다르므로 [[2.9.2. 신·구 명령 대응표]]의 비고를 함께 확인하세요
- 일부 명령은 보드 사양에 따라 지원되지 않을 수 있습니다 (예: 미디어 재생·주사율 설정은 DIBD520·720 전용) — 미지원 시 `F3` 응답
- 기존(구) 명령·속성은 그대로 동작합니다 (하위 호환)

## 2. 명령 구조

패킷 프레임은 기존과 같습니다: `![` + 주소 + Error Check + **명령** + 데이터 + `!]`

- 신 명령은 메시지 형식(M) 자리에 **두 글자 명령 코드**를 씁니다. 예: `![00K0!]`, `![00J050!]`, `![00V3 c_762a5db3!]`
- **값이 없으면 읽기, 값이 있으면 쓰기**로 동작하는 명령이 많습니다. 예: `![00J0!]` 밝기 읽기 / `![00J050!]` 밝기 50 쓰기
- 값을 **공백 1칸 뒤에** 쓰는 명령이 일부 있습니다 (예: `![00V3 {id}!]`, `![00V4 1!]`) — 대응표의 문법을 그대로 따라 주세요. 공백 유무가 다르면 형식 오류(F1)로 거부됩니다

## 3. 응답 규칙

응답 형태는 **통신 경로**에 따라 다릅니다:

| 경로 | 쓰기 명령 응답 |
| --- | --- |
| 시리얼 (RS-232/485/TTL) | **1글자** — 정상 `0` / 실패 `F` |
| 네트워크 (TCP/UDP/MQTT) | **적용된 값을 그대로 회신(echo)** |

조회(읽기) 응답은 형식이 두 가지입니다:

- 명령 코드 **바로 뒤에 값**이 붙으면 단일값 — 예: `![00J050!]` (밝기 50)
- 명령 코드 **뒤 공백 1칸 + `{...}`** 이면 JSON — 예: `![00NK {"board":"DIBD720U_16C",...}!]`

### 오류 코드

실패 응답은 `F` 뒤에 원인 숫자가 붙습니다. 대표적인 코드:

| 코드 | 의미 |
| --- | --- |
| `F1` | 형식 오류 (문법·자릿수·공백 불일치) |
| `F2` | 값 범위 초과 |
| `F3` | 기능 미지원 (구형 펌웨어 또는 해당 없는 보드) |
| `F4` | 실행 조건 불충족 |
| `F5` | 저장 실패 |
| `F7` | 내부 상태 오류 |

> [!tip]
> `F3`이 돌아오면 명령이 잘못된 게 아니라 **펌웨어가 그 기능을 아직 지원하지 않는 것**입니다. 펌웨어를 최신으로 업데이트한 뒤 다시 시도해 보세요.
