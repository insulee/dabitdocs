---
title: 2.11.2. Web API Integration Manual
---

> [!abstract] A guide for integration developers who control DB520 · DB720 LED displays over HTTP from POS systems, kiosks, or their own apps.
> It covers the calling conventions, 32 commands, building message text, preview, upload, and troubleshooting, based on measured responses (V4.2.0, 2026-09-04).
> The shipping firmware is **official V4.5.4**. The «does not work» statements in the text are V4.2.0 measurements. V4.5.4 is reported to fix them (not yet tested — see §11).

## 1. Six things to know first

- **Errors also return HTTP 200** — for `/api/v1/command`, the only success check is `code === 0` in the body. If you check only the HTTP status, you treat failures as successes
- **Command interval 100 ms (10 per second)** — on all paths. If you go faster, you get HTTP 429 + `{"code":429,"message":"Rate limit exceeded"}`. Serialize the calls through a single queue and space them 120 ms or more apart
- **Brightness has three units** — the write value of `set_brightness` is **0–99 percent** (0 = automatic sensor; 100 or more is rejected). `brightness` in the legacy `/status` is **a 0–255 byte** (measured 127 = 50%). `/api/v1/status` measured 50 on V4.2.0 — for the unit, see §12. Do not write a value that you read back without converting it
- **Concurrent connection limits** — 7 sockets, 2 MJPEG stream slots, and a 60-second receive and send timeout. Several polling clients use them up quickly
- **The board IP, model, and firmware change** — when your app starts, read `board_type` and `version` with `GET /api/v1/info`, and set the screen size from `panel_w` and `panel_h` in `/status`. Do not hard-code them
- **Factory default: no API key (no authentication)** — all 32 commands, including `reboot` and `factory_reset`, are open to the whole LAN, and there is no HTTPS. Do not expose the board outside the LAN (to the public internet)

## 2. Supported devices

- **Controllers**: DB520 · DB720 (firmware family DIBD520 · DIBD720). Support depends on the **firmware**, not on the model
- **Firmware**: the shipping version is **official V4.5.4**. The example responses in this document were measured on V4.2.0 (2026-09-03). The items fixed in V4.5.4 are collected in §11. The command list can differ by version, so check it with `GET /api/v1/actions`
- **Communication**: plain HTTP/1.1, port 80, no HTTPS, same LAN. The HEAD method returns 405 everywhere. There are no CORS headers, so browser JavaScript from another origin needs a proxy to call the API directly. `port: 5000` in `get_network` is a separate TCP ASCII command port and is outside the scope of this document

## 3. Endpoint map

| Path | Method | Purpose | Authentication |
| --- | --- | --- | --- |
| `/api/v1/info` | GET | Board type (`board_type`) and firmware version | None |
| `/api/v1/status` | GET | Brightness, automatic brightness, number of modules, uptime, boot count | None |
| `/api/v1/heap_status` | GET | Free memory (`psram`, `internal_sram`; no wrapper) | None |
| `/api/v1/storage/status` | GET | Storage status (no wrapper; without an SD card, `FAIL` + `NOT_SUPPORTED` is normal) | None |
| `/api/v1/actions` | GET | List of the 32 commands — the wrapper is `{code, actions[]}` (not `result`) | None |
| `/api/v1/command` | POST | Run a command — check `code` in the body | Optional |
| `/api/v1/system/www_upload` | POST | Upload web UI files (multipart) | **Required** |
| `/api/v1/system/api_key_rotate` | POST | Change the API key | **Required** |
| `/status` | GET | Legacy flat JSON — `panel_w`, `panel_h`, `power`, `stream_clients`, `cdepth`, `fw_ver` | None |
| `/panel.jpg` | GET | JPEG snapshot of the LED output | None |
| `/panel_stream` | GET | MJPEG stream of the LED output (2 slots) | None |
| `/` | GET | Built-in web interface `index.html` (503 + `Retry-After: 30` during an upload) | None |

> [!note] The response envelope is different for each endpoint — `/api/v1/info`, `status`, and `command` use `{code, result}`; `actions` uses `{code, actions}`; `heap_status`, `storage/status`, and the legacy `/status` are flat JSON without a wrapper. Do not use one parser for all of them.

## 4. Command calling conventions

- **Request**: `POST /api/v1/command`, `Content-Type: application/json`, body `{"action":"name","params":{...}}`. For a command without params, leave out `params` completely
- **Response**: `{"code":0,"result":{...}}`. On failure, `code ≠ 0` + `message`, and the original rejection can also come in `result`. Some commands return no `result` even on success
- **`code` values**: `0` success · `-1` the board rejected the command — measured `{"code":-1,"result":{"data":"J0F1","raw":"![00J0F1!]"},"message":"command failed"}` · `400` missing action or JSON error · `404` unregistered action · `429` rate limit (only in this case is the HTTP status also 429)
- **route** (the `route` field of `/api/v1/actions`): `cat` = converted to an ASCII command; the response `{data, raw}` passes the original through / `direct` = structured JSON / `msg` = message text sending (`send_*`) / `special` = handled directly as JSON (`reboot`, `factory_reset`, `schedule_apply_v2`)
- **How to read a cat response**: the first two characters of `data` are the command code, and the rest is the value. If one space + `{...}` follows, it is JSON (`K1 {"date":...}`). A rejection ends with `F` + a digit (`J0F1`) — `/F02` inside the message text is not a rejection

Measured examples (V4.2.0, request → response; all errors also come with HTTP 200):
```text
{"action":"get_network"}
→ {"code":0,"result":{"ip":"192.168.1.225","netmask":"255.255.255.0","gateway":"192.168.1.1","mac":"54:FF:22:00:00:02","port":5000,"is_dhcp":true,"device_name":"DB720U_08B          ","dns":"                             "}}
{"action":"get_brightness"}
→ {"code":0,"result":{"data":"J1/P0000/D9901/F0003/E0101/S2002/X0000/Y0000/B000/C3/G0/T0","raw":"![00J1/P0000/D9901/F0003/E0101/S2002/X0000/Y0000/B000/C3/G0/T0!]"}}
{}
→ {"code":400,"message":"Missing action field"}
{"action":"no_such_action"}
→ {"code":404,"message":"unknown action"}
```

## 5. The 32 commands

| action | params | Description |
| --- | --- | --- |
| `set_brightness` | `{value}` | Write the brightness, **0–99 percent**. 0 = automatic sensor (not off). 100 or more is rejected with `code -1` (`J0F1`) |
| `get_brightness` | none | Read the brightness. V4.2.0 returns only the attribute frame (`J1/P0000/...`) — no percent. Use the byte in `/status` 🔹V4.5.4: fixed to return percent (not yet tested) |
| `display_power` | `{on}` | LED power — ⚠ **fails in the V4.2.0 measurement** (`M5F3`; the old command M5 was removed). Use the official `P3`: `bridge_ascii {"cmd":"P","sub":"3","data":"1"|"0"}` → `P31`/`P30` (measured on V4.2.0). `{on}` accepts only a JSON boolean 🔹V4.5.4: HTTP path fixed (not yet tested) |
| `set_time` | `{time_str}` | Set the board time (for the format, see the yaml) |
| `get_time` | none | Read the time. Measured `K1 {"date":"260904","day":5,"time":"125853"}` |
| `set_screen_size` | `{w,h,layout}` | Screen size — **w/h are in pixels** (module counts are rejected with `F2`). It takes effect after you save and reboot |
| `get_screen_size` | none | Measured `H1 {"scan":0,"color":0,"method":0,"type":0}` — not w/h (it appears to be display settings). For the size, use `panel_w` and `panel_h` in `/status` 🔹V4.5.4: screen size query fixed (not yet tested) |
| `fill_screen` | `{color}` | Fill with one color, color index 0–7 🔹V4.5.4: it no longer changes the board settings and restarts, and a write without a value no longer returns success |
| `set_page_count` | `{count}` | Number of page messages |
| `delete_page` | `{page}` | Delete a page, 0–29 |
| `delete_realtime` | none | Delete the real-time message — rejected with `code -1` (`L2F1`) in the V4.2.0 measurement. `bridge_ascii` L2 also returns `L2F1` (firmware limit). To clear it, overwrite it with a new real-time message 🔹V4.5.4: real-time message deletion fixed (not yet tested) |
| `diagnostic` | none | Self-diagnosis |
| `test_pattern` | `{pattern}` | `off·red·green·blue·white·colorbar·grid·hstripe·border·spectrum·depthcheck`. Turns OFF automatically after 30 seconds |
| `send_realtime` | `{text}` | Real-time message. Put the attributes inline in the text (§6) |
| `send_page` | `{text}` | Page message. **Do not use the `page` parameter** — with it, you get `code 0`, but "00" appears before the text on the LED. Use only inline `/Pxxyy` |
| `reboot` | none | Reboot — wait until it finishes, then check the reconnection with `/api/v1/info` |
| `factory_reset` | none | Factory reset — deletes all settings. A confirmation step is required |
| `get_firmware_info` | none | Firmware information (direct) |
| `get_status` | none | Board status (direct; same structure as `/api/v1/status`) |
| `bridge_ascii` | `{cmd,sub,data}` | Pass an ASCII command through — **only categories G to Z**. Be careful with commands that can stop the board, such as `H0` (screen size) and `P0` (baud rate) |
| `set_video_source` | `{value}` | 0 = auto · 1 = webcam · 2 = schedule |
| `get_video_source` | none | Read the video source — `T1` + one digit (`T12` = 2) |
| `content_count` | none | Number of content items — 2-digit hexadecimal (`12` = 18 items) |
| `content_list` | none | List of content IDs (CSV) |
| `content_meta` | `{id}` | Content metadata |
| `play_content` | `{id}` | Play content |
| `stop_content` | none | Stop playback |
| `storage_stats` | none | Storage statistics. Measured `V5 {"raw":{"u":65,"f":11128}}` (the units of u/f are not confirmed) |
| `schedule_apply_v2` | `{json}` | Apply a schedule — all params form a ScheduleManifestV2 (see the yaml) |
| `schedule_status` | none | Measured `{"schedule_id":"","count":0,"etag":"\"0\"","current_entry_idx":0}` — detect changes with `etag` |
| `get_capabilities` | none | Measured `{"board_id":"DB720","storage":{"flash_dat":false,"littlefs":true,"sdcard":false,"raw_assets":true},"content_classes":[0,1,2,4,8,16,32,64,100,101,102,111]}` |
| `get_network` | none | `{ip,netmask,gateway,mac,port,is_dhcp,device_name,dns}` — see the §4 example. `device_name` and `dns` are padded with spaces to a fixed width, so **you must trim them** |

## 6. Building message text

- Put the attributes in the form `/letter+digits` **before the text**. Recommended order: `/P /D /E /S /F /C`. Example: `{"action":"send_realtime","params":{"text":"/P0000/E0100/S2002/F0203/C3어서오세요"}}` (어서오세요 = «Welcome»)
- `/Pxxyy` page (from 00) and section / `/Dxxyy` repeat (99 = infinite) and display method (00 normal, 01 immediate) / `/Exxyy` entry and exit effects — **exit `00` = no exit (the text stays)**, `01` stop / `/Sxxyy` effect speed and stay time (×0.5 seconds)
- `/Fxxyy` encoding and character size — **Korean text needs `/F02`** (JSON is sent as UTF-8; without this setting, the board reads it as EUC-KR and the text breaks) / `/Cx` text color (0 to 7), `/Gx` background color (0 to 7), `/Knn` 64 colors — for all effect codes and the color palette, see [[2.9.1. Introduction to the New ASCII Protocol]] · [[2.8.1. ASCII Protocol Manual]]

## 7. Preview video

- **Stream**: `GET /panel_stream?src=pgm&fps=15&q=70` — `multipart/x-mixed-replace` (MJPEG). You can put it directly in `<img src>`. It shares the 2 slots with `/stream` (camera), so open only one per app. Check the usage with `stream_clients` in `/status` — if it is `2`, more streams are rejected
- **Snapshot**: `GET /panel.jpg?t=<timestamp>` — the cache buster `?t=` is required (`Cache-Control: no-store`). Poll at intervals of **500 ms or more** (hardware JPEG encoding load). Measured: 1087 bytes on a 96×32 board
- In our measurements, the `q` (quality) parameter is ignored. JPEG compression causes **color bleeding**, so judge colors and color depth only by photographing the real display

## 8. Web UI file upload (advanced)

- `POST /api/v1/system/www_upload` — `multipart/form-data`, field name `files[]`, one part per file (no zip). **The `X-API-Key` header is required** — a board without a key returns HTTP 500 `auth not configured` (text/plain)
- **Set the first key only over a serial cable** — `![00WK={key}!]` (8–32 characters). The board rejects the first setting over the network. To change it later, use `api_key_rotate {"new_key":"..."}`
- Limit: **480KB** (over the limit: 413 `max 480KB`). File names must use ASCII letters and digits only. Names with `..` `/` `\` `:` return 400. You cannot use the reserved URLs (`/detect /stream /panel_stream /apply /status /test_pattern /panel.jpg /api/v1/*`) as file names
- **Non-atomic write** — each file is written to flash right away. If the upload stops in the middle, a partial state remains, so **upload `index.html` last**. During an upload, other clients get 503 for `/`

> [!warning] The web UI and the firmware are uploaded separately
> A firmware update (OTA) keeps the uploaded web UI (official V4.5.4). You replace the web UI separately (HEX 0x9E). Check the result with `![00W4!]` and the current web UI version with `![00W5!]`. A gradation check page was added to the web UI. In one case, requests for files other than `index.html` returned 404, so it is safer to put JS and CSS inline in a single HTML file

## 9. Integration checklist — 3 round trips

```text
# curl (bash) — 100 ms or more between lines

curl -s http://<board-IP>/api/v1/info
curl -s -X POST http://<board-IP>/api/v1/command -H "Content-Type: application/json" -d '{"action":"send_realtime","params":{"text":"/P0000/E0100/S2002/F0203/C3어서오세요"}}'
curl -s http://<board-IP>/api/v1/status

# PowerShell 7

Invoke-RestMethod http://<board-IP>/api/v1/info
Invoke-RestMethod http://<board-IP>/api/v1/command -Method POST -ContentType 'application/json; charset=utf-8' -Body '{"action":"send_realtime","params":{"text":"/P0000/E0100/S2002/F0203/C3어서오세요"}}'
Invoke-RestMethod http://<board-IP>/api/v1/status
```

- **Expected responses**: ① `board_type` matches your board, in a form like `{"code":0,"result":{"board_type":"DIBD720U_08B_08R020C","dibd_type":72,"version":"V4.2.0 2026-09-03"}}` ② `code` 0, and "어서오세요" («Welcome») appears on the LED (for the `result` format, see the yaml) ③ `code` 0, and `result.brightness`, `h_mdu`, `v_mdu`, and `uptime_s` exist
- If any of the three has `code ≠ 0`, go to §10. If the second one returns 429, the interval from the first call was less than 100 ms

## 10. Troubleshooting

| Symptom | Cause | Action |
| --- | --- | --- |
| HTTP is always 200, but nothing works | Errors also return 200 | Check `code` in the body. Check for `F` + a digit at the end of `message` and `result.data` |
| HTTP 429 `Rate limit exceeded` | The 100 ms interval was violated (10 per second) | Serialize the calls through a single queue, space them 120 ms or more apart, and retry after a short wait on 429 |
| `set_brightness` 100 returns `code -1` (`J0F1`) | The percent range is 0–99 | Use 99 or less. 0 is the automatic sensor (not off) |
| `display_power {"on":1}` turns the display off | Only a JSON boolean is accepted; numbers and strings are false | `{"on":true}` / `{"on":false}` |
| "00" appears before the `send_page` text | Defect of the `page` parameter (`code 0`, but the text breaks) | Remove `page` and put `/Pxxyy` inline in the text |
| Connection refused, or the stream does not open | More than 7 sockets or 2 stream slots, 60-second timeout | Reduce the polling clients, use one stream, check `stream_clients` in `/status` |
| `bridge_ascii` H4 (background image) is rejected with `F3` | Firmware limit of the HTTP bridge — only TCP:5000 works | Use the text attribute `/Bnnn` instead (`send_realtime {"text":"/B001"}` = background only, `"/B001어서오세요"` = background + text; confirmed on a real V4.2.0 board). However, the `/panel.jpg` preview does not show the background |
| `display_power` returns `code -1` (`M5F3`) | The old command M5 was removed, and the bridge was not updated (measured on V4.2.0) | Control the power with `bridge_ascii P3 1/0` |
| `get_brightness` does not return percent (`J1/P0000/...`) | V4.2.0 returns the default attribute frame | Convert the `brightness` byte in `/status`. `/B000` in the frame is the background image number, not the brightness |

## 11. Fixed in V4.5.4 (based on the V4.3.0 release notes · not yet tested)

The firmware V4.3.0 release notes say that they fixed «nine items that did not work over HTTP». The fixes are in the shipping version, official V4.5.4. The table below lists the five items that the release notes name, and two items that were blocked at the same time (the release notes do not name the other four items). **We have not tested them yet**, so the V4.2.0 measurements in the text above stay as they are.

| Item | V4.2.0 measured (text) | V4.5.4 (release notes) |
| --- | --- | --- |
| Power | `display_power` rejected with `M5F3` | Fixed |
| Screen size query | `get_screen_size` does not return w/h | Fixed |
| Brightness query | No percent in `get_brightness` | Fixed to return percent |
| Background image | `bridge_ascii` H4 rejected with `F3` | Fixed |
| Real-time message deletion | `delete_realtime` rejected with `L2F1` | Fixed |
| Screen fill | — | It no longer changes the board settings and restarts |
| Write without a value | — | It no longer returns success |

> [!warning] Not yet tested
> The release notes do not give the actual response format after the fix (for example, whether `get_screen_size` returns w/h). We will update the text when we confirm it on a V4.5.4 board

## 12. Not yet confirmed (kept separate)

- **HTTP path for background image H4** — `bridge_ascii` H4 is rejected with `F3` (measured on V4.2.0; reported as fixed in V4.5.4 but not yet tested — §11). The text attribute `/Bnnn` works. The missing background layer in the preview (`/panel.jpg`, `/panel_stream`) is still under firmware review
- **Text readback command** — there is no command that returns the text on the display now. Your integration app must keep the last value that it sent
- **Remote access path (outside the LAN)** — there is no defined path, because the API assumes plain text and no authentication. Decide on a VPN or other option after you check the network policy of the site
- **Behavior of the "optional" authentication path after an API key is set** — it is not confirmed yet whether `command` and others then require the key, and whether the web interface keeps working
- **Real-time message deletion** — both `delete_realtime` and `bridge_ascii` L2 are rejected with `L2F1` (measured on V4.2.0; reported as fixed in V4.5.4 but not yet tested — §11). No official deletion path is confirmed yet — overwrite the message instead
- **Unit of brightness in `/api/v1/status`** — the legacy `/status` always uses a byte (127 = 50%). `/api/v1/status` measured 50 on V4.2.0. The unit needs to be checked on V4.5.4

> [!note] Do not use the items above in customer guidance, proposals, or quotes until they are confirmed. When they are confirmed, we move them from this section into the main text.
