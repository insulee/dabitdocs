title: 2.9.2. New and Legacy Command Mapping Table
---

> [!abstract] The extended ASCII commands of the new controllers by function, and how they map to the existing (legacy) numeric commands
> Read [[2.9.1. Introduction to the New ASCII Protocol]] first for the command structure and the response rules.

> [!note] How to read the tables
> - **Legacy command**: the existing two-digit numeric special command code (in the form `![0042!]`). "New" means a function that the new controllers added
> - **Response**: `0/F` = write ACK (serial), `JSON` = JSON after one space, `echo` = returns the value that you sent
> - For safety, management and diagnostic commands that are not listed here (such as factory reset) are given only on request — contact customer support

## 1. System and information queries

| New command | Function | Legacy command | Response | Notes |
| --- | --- | --- | --- | --- |
| `![00M1!]` | System (firmware) information string | `81` | Information string | |
| `![00M2!]` | Firmware version details | `97` | JSON | |
| `![00NJ!]` | Firmware version and build date | New | JSON | `{"v":"...","date":"..."}` |
| `![00NK!]` | All board information (model, version, color capability, screen size) | New | JSON | Recommended for device identification in integrations |
| `![00NF!]` | Memory and uptime | New | JSON | |
| `![00NI!]` | Boot information and reset reason | New | JSON | |
| `![00NG!]` | Network status (Ethernet, IP, MQTT) | New | JSON | |
| `![00NC!]` / `![00ND!]` / `![00NE!]` | USB / SD / internal storage status | New | JSON | Boards without support return `F` |
| `![00NA!]` | Display performance (fps and more) | New | JSON | |

## 2. Time and screen control

| New command | Function | Legacy command | Response | Notes |
| --- | --- | --- | --- | --- |
| `![00K0{YYMMDD}{d}{HHMMSS}!]` write / `![00K0!]` read | Set and read the time (RTC) — d = day of the week (0 = Sunday to 6 = Saturday)<br>In a read response, Sunday is 0 or 7, depending on the board — read both as Sunday<br>In the JSON format (`![00K0{"date":…,"day":N,"time":…}!]`, ESP-based boards only), `day` is 1 = Monday to 7 = Sunday · 0 returns `F2` | `30`/`31` | `0/F` · JSON | Reads when there is no value |
| `![00H0!]` | Read the screen size (**in pixels**) | `40`/`43` | JSON | The legacy command used module units |
| `![00H2S{pattern}!]` write / `![00H2!]` read | Set and read the display signal (scan pattern) | `44`/`45` | echo `![00H2 S{pattern}!]` | **V3.8.3+**. A space in the value returns `F5`. The legacy commands `![0044 pattern!]` (one space) and `![0045!]` need **V3.2.8 or later** — see the special command table in [[2.8.1. ASCII Protocol Manual]] |
| `![00H3!]` read / `![00H3{n}!]` set (V4.4.0 or earlier) | Read the color mode (0 = 8 colors / 1 = 256 colors / 2 = 16-bit) · V4.4.0 or earlier can also set it | `47`/`48` | JSON | **From the official V4.5.4, there is no command to select the color depth (H3 write) — the firmware file sets the color depth (256 colors on all models).** The `![00H3!]` query stays (in V4.5.4 it includes the `"out"` key with the actual number of output colors). A query shows 24-bit (24C) as read-only. The legacy command `47` (`![00470!]` 8 colors / `![00471!]` 256 colors) was used only in V3.8.3 to V4.4.0 and was removed in V4.5.4 together with H3 write — in versions before V3.8.3, the build fixes it. See [7.5. Color Mode Switching](https://docs.dabitsol.com/7.5) (Korean) |
| `![00H4{nnn}!]` | Show a background image (000–255) | `20` | `0/F` | |
| `![00H6{0~7}!]` | Fill the screen with one color | `70` | `0/F` | |
| `![00H7{NNNN}!]` / `![00H7!]` | Set and read the target refresh rate (Hz) of the screen — 0000 = auto | New | echo · JSON | No reboot needed. **DIBD520 · 720 only** (DB520 · DB720 boards; others return `F3` — measured) |
| `![00J0{NN}!]` / `![00J0!]` | Set and read the brightness (00 = auto, 01–99) | `50`/`51` | `0/F` · single value | |
| `![00J3{NN}!]` | Blink count (01–20) | `55` | `0/F` | **V4.5.4 or later returns an error for out-of-range values (00, 21, and so on).** V4.4.0 or earlier accepts 00–21 (00 and 21 = 8 times) |
| `![00J4{HHVV}!]` | Font weight (horizontal and vertical, each from 10 to 30 = from 1.0× to 3.0×) | `56` | `0/F` | V4.5.4 or later returns an error for values outside 10–30 |

## 3. Display and messages

| New command | Function | Legacy command | Response | Notes |
| --- | --- | --- | --- | --- |
| `![00L0{NN}!]` | Number of page messages (01–10) | `60` | `0/F` | |
| `![00L1{NN}!]` | Delete pages (00–09, 99 = all) | `61` | `0/F` | |
| `![00L2!]` | Delete the real-time message | `62` | `0/F` | |
| `![00P3{0\|1}!]` | LED power OFF/ON | `21` | `0/F` | |
| `![00P4!]` | Restore the screen (clear the diagnostic screen + play the schedule) | New | `0/F` | Restores without a reboot |
| `![00NB{0~9,A}!]` | Diagnostic test pattern (0 = clear, 5 = color bar, and more) | New | echo | V4.4.0 or earlier: clears automatically after 30 seconds. **V4.5.4 or later: does not turn off by itself — clear it with `![00NB0!]`** |
| `/K{nn}` attribute | 64-color text color | New | — | See [[2.9.3. 64-Color Text (K Attribute)]]. **Checked on V4.1.3** — earlier versions have only the 8 colors of `/C` and `/G`. **Removed from V4.4.1** — the official V4.5.4 has 36 colors for `/C` and `/G` and `#RRGGBB` ([[2.8.1. ASCII Protocol Manual]]) |

## 4. Media playback (new content)

| New command | Function | Legacy command | Response | Notes |
| --- | --- | --- | --- | --- |
| `![00V3 {id}!]` | Play media content (one space + content id) | New | JSON echo | **DIBD520 · 720 only** (other models return `F`) |
| `![00V4 1!]` | Stop media playback (**the argument ` 1` is required**) | New | JSON echo | Without the argument: `F1`. DIBD520 · 720 only |

> [!note]
> Media file upload, list, and delete use a separate network API, not ASCII. In DabitOne, the `미디어 재생` (Media playback) window does this for you — see [2.7.5. Media Playback](https://docs.dabitsol.com/2.7.5) (Korean). Media content and content of the existing method (playlists) are **not stored on the LED display at the same time** (sending one deletes the other).

## 6. Firmware and web UI (V4.5.4 or later)

| New command | Function | Legacy command | Response | Notes |
| --- | --- | --- | --- | --- |
| `![00U4!]` read / `![00U4 0!]` · `![00U4 1!]` switch | Read the versions in the two OTA slots (ota_0 · ota_1) / boot from that slot | New | Version information · reboot | DB400 · DB402 · DB502 · DB520 · DB720. For «save only» OTA and automatic rollback, see [2.10.1. Reading Firmware Information and Uploading Firmware](https://docs.dabitsol.com/2.10.1) (Korean) |
| `![00W4!]` / `![00W5!]` | Result of the board web UI replacement / read the current web UI version | New | Result · version | DB520 · DB720. The web UI is uploaded separately from the firmware — [[2.11.1. Web Interface User Manual]] |

> [!warning] Management commands
> To prevent mistakes, this table does not list commands that greatly change the device state, such as factory reset, reboot, and MAC change. If you need them, contact customer support.
