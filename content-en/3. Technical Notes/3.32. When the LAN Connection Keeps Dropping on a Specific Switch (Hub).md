---
title: 3.32. When the LAN Connection Keeps Dropping on a Specific Switch (Hub)
---

> [!abstract] The cause and fix when the LAN link keeps connecting and dropping on a specific switch (hub)
> The cause is a defect in the EEE (Energy Efficient Ethernet) function of the switch. Replace the switch, or fix the controller to 10M

#### Symptoms

- When you connect the controller to a specific switch (hub), **the link connects and drops about every 2 seconds** (the link LED of the switch port blinks regularly)
- In both DabitOne and DabitChe, **the TCP connection keeps failing** or drops often (the device is found in a search, but you cannot connect)
- **The same controller works normally on another switch or router**
- Switches with confirmed problems: some low-cost unmanaged switches, such as the **NEXI NX-SG1005N**

#### Cause — the EEE (Energy Efficient Ethernet) function of the switch

EEE (Energy Efficient Ethernet) is a power-saving function of a switch. It turns the signal off for a short time when no data is sent or received.

- Some low-cost switches have a defect in this function: **when they connect at 100M, they go into power-saving mode and then drop the link**
- **The controller is not faulty** — the link negotiation completes normally each time, but the link does not stay up
- EEE works only at 100M or higher, so **connecting at 10M keeps this function out and fixes the problem**

#### How to fix it (choose one of three)

| Method | Applies to | Description |
| --- | --- | --- |
| ① Replace the switch (hub) | All cases | Replace it with a switch or router that is known to work. The surest method |
| ② Turn off EEE on the switch | Managed switches | Turn off the EEE (or Green Ethernet) function in the management screen of the switch |
| ③ Fix the controller to 10M | Firmware V4.1.0 or later | Change the controller to 10M only with the commands below. For sites where you cannot replace the switch |

> [!tip] 10M does not make it slower
> Measurements show the same response speed and file transfer speed at 10M and 100M. The 10M bandwidth is enough for LED display data.

#### Commands to fix 10M

- Supported firmware: **V4.1.0 or later** (to check the version, see [3.21. Reading Controller Firmware Information](https://docs.dabitsol.com/3.21) (Korean))
- For earlier versions, **request the 10M-only firmware separately**
- Send path: UDP (5108) or serial (115200) — you can send even when TCP does not work

| Command | Action |
| --- | --- |
| `![00NG!]` | Reads the current state → `{"eth":"UP","ip":"...","lmode":N,"l10m":N}` |
| `![00NG1!]` | **Fixes 10M** (saves the setting; applies after a reboot) |
| `![00NG2!]` | Fixes auto (including 100M) (applies after a reboot) |
| `![00NG0!]` | Clears the setting — back to the firmware default |

- `lmode` = the saved setting (1 = fixed 10M / 2 = auto / 0 or 255 = not set)
- `l10m` = the current state (1 means only 10M is in use)

> [!note] Always reboot after the command
> The setting command only saves the value. It does not apply it at once. If the response has `reboot:1`, the value is saved, and **it applies after a reboot**. After the reboot, check `lmode:1` and `l10m:1` with `![00NG!]`.

#### Example procedure

1. Send `![00NG1!]` → check the response `{"lmode":1,"l10m":1,"reboot":1}`
2. Reboot the controller (turn the power off and on)
3. Send `![00NG!]` → check `lmode:1` and `l10m:1`
4. Check that the link stays stable and that you can connect with TCP

> [!warning] Cautions
> - **A factory reset clears this setting.** If the same symptom comes back after a reset, send `![00NG1!]` again.
> - **The command cannot reach a controller whose link is completely down.** In that case, ① connect it for a short time to a switch that works (for example, directly to a router), set it, and move it back, or ② send the command over serial (115200).
