title: 3.20. BCC Calculation for the ASCII Protocol
---

> [!abstract] BCC calculation and use in the Dabit Solution ASCII protocol
> BCC (Block Check Character) is a simple method to detect errors when a data block is sent. It uses a value made with XOR operations. This document explains how to calculate the BCC in the Dabit Solution ASCII string protocol. It also shows examples of command packets with a BCC.

#### What is BCC (Block Check Character)?

- BCC is a simple method to detect errors in a data block
- It is a value made with an operation (usually XOR) before the data is sent. It shows whether the data was damaged while it was sent and received

#### How to set error detection in ASCII protocol command and response packets
- Use the `E` part of the command packet (`![AEM/ ... !]`) to set error detection
	- `"0"`: do not use error detection
	- `"1"`: add the BCC (error detection character) value after the end characters
	- The BCC calculation includes the start characters and the end characters
- Command packet example: `![010/C2ABCD!]6D`
- Response packet example: `![0100!]07`

#### How to send a packet with a BCC and detect errors
1. Take the full data string (`![......!]`), including the start character (`!`) and the end character (`]`), and look up the ASCII value of each character
2. Convert each ASCII value to an 8-bit binary number
3. XOR all the converted values
4. Convert the final result to hexadecimal
5. Add the result to the end of the data and send it
	- If the controller returns a response packet, the packet was sent correctly
	- If the result does not match the BCC that the controller calculates, the controller does not apply the packet. This detects errors and keeps the communication reliable
#### BCC calculation example 1 — digits and Latin letters
0. String: `![010/C2ABCD!]`
1. Look up the ASCII value of each character
	- `!` = `0x21 (33)`
	- `[` = `0x5B (91)`
	- `0` = `0x30 (48)`
	- `1` = `0x31 (49)`
	- `0` = `0x30 (48)`
	- `/` = `0x2F (47)`
	- `C` = `0x43 (67)`
	- `2` = `0x32 (50)`
	- `A` = `0x41 (65)`
	- `B` = `0x42 (66)`
	- `C` = `0x43 (67)`
	- `D` = `0x44 (68)`
	- `!` = `0x21 (33)`
	- `]` = `0x5D (93)`
2. Convert the ASCII values to 8-bit binary numbers
	- `! (0x21)` = `00100001`
	- `[ (0x5B)` = `01011011`
	- `0 (0x30)` = `00110000`
	- `1 (0x31)` = `00110001`
	- `0 (0x30)` = `00110000`
	- `/ (0x2F)` = `00101111`
	- `C (0x43)` = `01000011`
	- `2 (0x32)` = `00110010`
	- `A (0x41)` = `01000001`
	- `B (0x42)` = `01000010`
	- `C (0x43)` = `01000011`
	- `D (0x44)` = `01000100`
	- `! (0x21)` = `00100001`
	- `] (0x5D)` = `01011101`
3. XOR the values (initial value: `00000000`)
    - `00000000` ^ `00100001(!)` = `00100001`
    - `00100001` ^ `01011011([)` = `01111010`
    - `01111010` ^ `00110000(0)` = `01001010`
    - `01001010` ^ `00110001(1)` = `01111011`
    - `01111011` ^ `00110000(0)` = `01001011`
    - `01001011` ^ `00101111(/)` = `01100100`
    - `01100100` ^ `01000011(C)` = `00100111`
    - `00100111` ^ `00110010(2)` = `00010101`
    - `00010101` ^ `01000001(A)` = `01010100`
    - `01010100` ^ `01000010(B)` = `00010110`
    - `00010110` ^ `01000011(C)` = `01010101`
    - `01010101` ^ `01000100(D)` = `00010001`
    - `00010001` ^ `00100001(!)` = `00110000`
    - `00110000` ^ `01011101(])` = `01101101`
4. Convert the XOR result to hexadecimal
    - `01101101` = `0x6D`
5. Send it with the ASCII protocol (DabitOne or the DABIT Protocol Simulator (DBPS))
	 - `아스키 프로토콜 [OK] ![010/C2ABCD!]6D`
        `Receive : ![0100!]07`
	 - These are log lines from the program. `아스키 프로토콜` means «ASCII protocol».
#### BCC calculation example 2 — Korean characters
0. String: `![010/C2가나다!]` (**use the EUC-KR encoded values of Korean characters**)
1. Look up the value of each character
    - ASCII (1 byte)
        - `!` = `0x21 (33)`
        - `[` = `0x5B (91)`
        - `0` = `0x30 (48)`
        - `1` = `0x31 (49)`
        - `0` = `0x30 (48)`
        - `/` = `0x2F (47)`
        - `C` = `0x43 (67)`
        - `2` = `0x32 (50)`
        - `!` = `0x21 (33)`
        - `]` = `0x5D (93)`
    - EUC-KR (2 bytes)
        - `가` = `0xB0 0xA1`
        - `나` = `0xB3 0xAA`
        - `다` = `0xB4 0xD9`
2. Convert the values to 8-bit binary numbers
    - `! (0x21)` = `00100001`
    - `[ (0x5B)` = `01011011`
    - `0 (0x30)` = `00110000`
    - `1 (0x31)` = `00110001`
    - `0 (0x30)` = `00110000`
    - `/ (0x2F)` = `00101111`
    - `C (0x43)` = `01000011`
    - `2 (0x32)` = `00110010`
    - `가1 (0xB0)` = `10110000` / `가2 (0xA1)` = `10100001`
    - `나1 (0xB3)` = `10110011` / `나2 (0xAA)` = `10101010`
    - `다1 (0xB4)` = `10110100` / `다2 (0xD9)` = `11011001`
    - `! (0x21)` = `00100001`
    - `] (0x5D)` = `01011101`
3. XOR the values (initial value: `00000000`)
    - `00000000` ^ `00100001(!)` = `00100001`
    - `00100001` ^ `01011011([)` = `01111010`
    - `01111010` ^ `00110000(0)` = `01001010`
    - `01001010` ^ `00110001(1)` = `01111011`
    - `01111011` ^ `00110000(0)` = `01001011`
    - `01001011` ^ `00101111(/)` = `01100100`
    - `01100100` ^ `01000011(C)` = `00100111`
    - `00100111` ^ `00110010(2)` = `00010101`
    - `00010101` ^ `10110000(가1)` = `10100101`
    - `10100101` ^ `10100001(가2)` = `00000100`
    - `00000100` ^ `10110011(나1)` = `10110111`
    - `10110111` ^ `10101010(나2)` = `00011101`
    - `00011101` ^ `10110100(다1)` = `10101001`
    - `10101001` ^ `11011001(다2)` = `01110000`
    - `01110000` ^ `00100001(!)` = `01010001`
    - `01010001` ^ `01011101(])` = `00001100`
4. Convert the XOR result to hexadecimal
    - `00001100` = `0x0C`
5. Send it with the ASCII protocol (DabitOne or the DABIT Protocol Simulator (DBPS))
	-  `아스키 프로토콜 [OK] ![010/C2가나다!]0c`
		`Receive : ![0100!]07`
