
> [!abstract] 메시지 종류
> 실시간(긴급) 메시지와 페이지(일반) 메시지의 특징과 차이점 

#### 실시간 메시지

1. 특징:
    - 자주 변경되는 데이터를 즉시 표시하는 방식
    - RAM 메모리에 임시 저장되며, 전원이 꺼지면 데이터가 삭제
    - 우선 순위가 높아, 페이지 메시지 표시 중에도 실시간 메시지가 전송되면 즉시 표시
    - 주로 긴급한 정보를 표시하거나 실시간 데이터를 업데이트하는 데 사용
2. 예시:
    - ASCII 패킷: `![000/P0000/실시간메시지!]`
    - `000`: 실시간 메시지 패킷을 의미
3. 장점:
    - 즉각적인 반응성
    - 단발성 메시지 전송에 적합
    - 처리 속도가 빠름

#### 페이지 메시지

1. 특징:
    - 변경이 적은 안내, 홍보, 주의 문구 등을 페이지 순서대로 무한 반복 표시
    - 플래시 메모리에 저장되어 전원이 꺼져도 데이터가 유지
    - 플래시 메모리는 10만번정도 쓰기가 반복되면 손상될 가능성이 있으므로, 실시간으로 변하는 메시지는 실시간 문구로 전송
    - 최대 10개의 메시지를 미리 등록해 사용
2. 예시:
    - ASCII 패킷: `![001/P0100/페이지메시지!]`
    - `001`: 페이지 메시지 패킷을 의미
    - `P0000`: 1번 페이지 메시지, `P0100`: 2번 페이지 메시지 ... `P0900`: 10번 페이지 메시지
3. 장점:
    - 전원이 꺼져도 데이터 유지
    - 지속적인 안내 문구나 광고에 적합
    - 시스템 부하를 줄임
4. **주의사항**
	- 정확한 표출을 보장하기 위해, 프로토콜 패킷은 반드시 하나씩 전송한 뒤 컨트롤러의 응답을 확인한 후 다음 패킷을 전송 (최소 200ms 이상의 간격 유지 권장)

#### 주요 차이점

| 항목       | 실시간 메시지                    | 페이지 메시지                    |
| -------- | -------------------------- | -------------------------- |
| 저장 위치    | RAM (휘발성 메모리)              | 플래시 메모리 (비휘발성)             |
| 표시 우선 순위 | 페이지 메시지보다 우선 표시            | 실시간 메시지 우선 표시              |
| 용도       | 긴급 데이터 전송 및 즉각 반영          | 주기적 안내, 광고 등 반복 표시         |
| 데이터 보존   | 전원 OFF 시 데이터 손실            | 전원 OFF 시에도 데이터 유지          |
| 응답 속도    | RAM에 저장되어 처리 속도가 빠름        | 플래시 메모리에 쓰기 작업이 필요하여 약간 느림 |
| 예시 상황    | 차량 번호판 표시, 긴급 경고 등 실시간 데이터 | 주차 안내, 광고 문구, 정적인 정보 표시    |

#### 추천 사용 사례

- 실시간 메시지: 긴급 상황(예: 출입 금지), 동적 데이터(예: 남은 주차 공간 표시, 자동차번호판)
- 페이지 메시지: 고정된 안내 문구(예: 환영합니다) 및 반복 광고 메시지

#### DBPS에서 전송 방법
1. 실시간메시지
	- 헥사프로토콜 
		- 메시지 종류 > `실시간 메시지`
		- 문자색상 및 문구 입력 후 전송
	- 아스키프로토콜
		- `![000/P0000/실시간메시지!]`
2. 페이지메시지
	- 설정 > 페이지 메시지 설정 > 총 개수 설정 > `**개` > `전송` > `닫기`
	- 헥사프로토콜
		- 메시지 종류 > `페이지 메시지` > 페이지 > `**번`
		- 문자색상 및 문구 입력 후 전송
	- 아스키프로토콜
		- `![001/P0100/페이지메시지!]`
