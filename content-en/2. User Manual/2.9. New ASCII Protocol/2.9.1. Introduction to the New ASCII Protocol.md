title: 2.9.1. Introduction to the New ASCII Protocol
---

> [!abstract] Extensions to the ASCII protocol for the new controllers (DB520 · DB720, firmware family DIBD520 · DIBD720) — command structure, response rules, and supported versions
> The basic packet frame is the same as in [2.8.1. ASCII Protocol Manual](https://docs.dabitsol.com/2.8.1) (Korean). This chapter covers only the commands added in the new firmware.

## 1. Supported devices

- **Controllers**: support depends on the **firmware**, not on a specific model — all DIBD500 · 600 · 520 · 720 families are supported (tested on real DIBD500S · 600T · 720U boards with V4.1.3)
- **Firmware**: supported step by step from **V3.6.0 or later** — each command needs a different version, so also check the notes in [2.9.2. New and Legacy Command Mapping Table](https://docs.dabitsol.com/2.9.2) (Korean)
- Some commands may not be supported, depending on the board specification (for example: media playback and refresh rate settings are only for DIBD520 · 720) — if a command is not supported, the response is `F3`
- The existing (legacy) commands and attributes still work (backward compatible)

## 2. Command structure

The packet frame is the same as before: `![` + address + Error Check + **command** + data + `!]`

- A new command uses a **two-character command code** in the position of the message format (M). Examples: `![00K0!]`, `![00J050!]`, `![00V3 c_762a5db3!]`
- Many commands **read when there is no value, and write when there is a value**. Example: `![00J0!]` reads the brightness / `![00J050!]` writes brightness 50
- Some commands put the value **after one space** (examples: `![00V3 {id}!]`, `![00V4 1!]`) — use the syntax in the mapping table exactly. If the space does not match, the controller rejects the command with a format error (F1)

## 3. Response rules

The response format depends on the **communication path**:

| Path | Response to a write command |
| --- | --- |
| Serial (RS-232/485/TTL) | **1 character** — success `0` / failure `F` |
| Network (TCP/UDP/MQTT) | **Returns (echoes) the applied value** |

A query (read) response has one of two formats:

- If the **value comes directly after the command code**, it is a single value — example: `![00J050!]` (brightness 50)
- If **one space + `{...}`** comes after the command code, it is JSON — example: `![00NK {"board":"DIBD720U_16C",...}!]`

### Error codes

A failure response has a cause number after `F`. Common codes:

| Code | Meaning |
| --- | --- |
| `F1` | Format error (syntax, number of digits, or space mismatch) |
| `F2` | Value out of range |
| `F3` | Function not supported (old firmware, or a board without the function) |
| `F4` | Conditions for execution not met |
| `F5` | Save failed |
| `F7` | Internal state error |

> [!tip]
> If you get `F3`, the command is not wrong. **The firmware does not support that function yet.** Update the firmware to the latest version and try again.
