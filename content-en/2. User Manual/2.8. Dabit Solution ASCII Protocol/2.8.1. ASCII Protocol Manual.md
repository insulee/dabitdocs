## 1. Basic protocol structure

### 1.1. Protocol command packet
#### Command packet: `![AEM...!]`

| Item | Meaning | Content |
| ----- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `![` | Start characters | Start of the packet |
| `A` | Address | LED display address (Destination) <br>- Single mode (1:1 communication): use `0(default)` as the destination address of the LED display <br>- Multi mode (1:n communication): for RS-485 communication, the LED display address is a value from `1~F`, and you set the DIP switch of the RS-485 board to the same value |
| `E` | Error Check | - `0`: do not use error checking <br>- `1`: add a 2-byte BCC (error detection character) value after the end characters <br>Example 1) `![010ABCD!]33` <br>Example 2) `![010/C3123/C6ABC!]42` |
| `M` | Message format | - `0`: real-time message <br>- `1`: page message <br>- `XX`: special command code. Applies from firmware 7.5. |
| `...` | Data | Text display attributes and text content |
| `!]` | End characters | End of the packet |
- For details of the Error Check, see [[3.20. BCC Calculation for the ASCII Protocol]]
- For real-time and page messages, see [[2.5.1. Message Types]]
- For the text display attributes and the text content, see [[#2. Text display attributes|Text display attributes]]

### 1.2. Protocol response packet
#### Response packet: `![0EMR!]`

| Item | Meaning | Content |
| ---- | ----------- | ---------------------------------------- |
| `![` | Start of the packet | |
| `0` | Address | The returned address is always `0` |
| `E` | Error Check | Same as in the protocol command packet |
| `M` | Message format | Same as in the protocol command packet |
| `R` | Receive status value | - `0`: data processed normally. <br>- `F`: data processing failed. |
| `!]` | End characters | End of the packet |

### 2.2. Attribute code definitions and examples

#### 2.2.1. /Pxxyy

- xx: page number
	- Sets the page number
	- (Important) 00: page 1, 01: page 2
		- Example: `![001/P0000/C1Hello!]` - registers a red Hello on page 1
	- In a real-time message packet, the page number has no meaning
- yy: section number
    - You can divide one screen into 2 or more sections (up to 4 sections)
    - Each section can have its own attributes

#### 2.2.2. /Dxxyy

- xx: display control
    - `00`: do not display the text
    - `1~98`: number of times to repeat the text
    - `99`: repeat the text without limit
- yy: display method
    - `00`: normal display (shows the new text after the current text finishes)
    - `01`: immediate display (stops the current text and shows the new text)
- Practical example: if you resend a frequently updated section (vehicle number, temperature, and so on) with `yy=01` (immediate display), the effects of the other sections on the screen also restart. To change only the updated section, first send individual effect display (`![0062Y!]`). Then send that section with `/D9900` (repeat without limit, normal display) — see the [[2.5.3. Simultaneous and Individual Effects per Section|2.5.3 practical example]]

#### 2.2.3. /Fxxyy

- xx: character encoding and font
	- System -- A --> Controller -- B --> LED module
	- `00` - A: EUC-KR code (2 bytes), B: Korean Johab font (2 bytes)
	- `01` - A: UTF-16 code (2 bytes), B: Unicode font (2 bytes)
	- `02` - A: UTF-8 code (3 bytes), B: Korean Johab font (2 bytes)
	- `03` - A: UTF-8 code (3 bytes), B: Unicode font (2 bytes)
- yy: font size (horizontal pixels x vertical pixels)
    - `01` - Latin letters/digits: 7x14 / Korean: 14x14
    - `02` - Latin letters/digits: 6x12 / Korean: 12x12
    - `03` - Latin letters/digits: 8x16 / Korean: 16x16
    - `04` - Latin letters/digits: 10x20 / Korean: 20x20
    - `05` - Latin letters/digits: 12x24 / Korean: 24x24
    - `06` - Latin letters/digits: 14x28 / Korean: 28x28
    - `07` - Latin letters/digits: 16x32 / Korean: 32x32
    - `08` - Latin letters/digits: 18x36 / Korean: 36x36
    - `09` - Latin letters/digits: 20x40 / Korean: 40x40
    - `10` - Latin letters/digits: 22x44 / Korean: 44x44
    - `11` - Latin letters/digits: 24x48 / Korean: 48x48
    - `12` - Latin letters/digits: 26x52 / Korean: 52x52
    - `13` - Latin letters/digits: 28x56 / Korean: 56x56
    - `14` - Latin letters/digits: 30x60 / Korean: 60x60
    - `15` - Latin letters/digits: 32x64 / Korean: 64x64
- To use two or more font sizes on one screen, divide the screen into sections (`/Pxxyy`, `/Xxxyy`, `/Yxxyy`) and set the font size for each section

#### 2.2.4. /Exxyy

- xx: entry effect
- yy: exit effect
- For the effects, see [[3.23. Message Entry and Exit Effect Codes]]

#### 2.2.5. /Sxxyy

- xx: effect speed
	- Value: `00`~`99`
	- A smaller value means a relatively faster speed
- yy: stay time
    - Value: `00`~`99`
    - The time that the text stays on the screen after it appears
    - Stay time = value x 0.5 seconds
- Example: `S2004` means effect speed 20 and stay time 2 seconds

#### 2.2.6. /Xxxyy
- xx: horizontal start position
	- Value: `00` (not set)~`99`
	- Set the start position in 4-pixel units from the left edge
	- Example: if the value is `02`, the display starts at the 9th pixel, 8 pixels from the left edge
- yy: horizontal end position
	- Value: `00` (not set)~`99`
	- Set the end position in 4-pixel units from the left edge
	- Example: if the value is `08`, the display ends at the 32nd pixel, 32 pixels from the left edge

#### 2.2.7. /Yxxyy
- xx: vertical start position
	- Value: `00` (not set)~`99`
	- Set the start position in 4-pixel units from the top edge
	- Example: if the value is `02`, the display starts at the 9th pixel, 8 pixels from the top edge
- yy: vertical end position
	- Value: `00` (not set)~`99`
	- Set the end position in 4-pixel units from the top edge
	- Example: if the value is `08`, the display ends at the 32nd pixel, 32 pixels from the top edge


#### 2.2.8. /Bxxx
- xxx: background image list number
    - Make a background image in the DabitOne software and save it to the controller. Then call its number to show it on the LED display (see [3.3. Making and Showing Background Images](https://docs.dabitsol.com/3.3) (Korean))
    - `000` : no background image
    - `001~255` : number of a saved background image
    - Example: `![000/B003!]` : shows background image 3


#### 2.2.9. /Cx
- x: text color setting
    - 0 : Black
    - 1 : Red
    - 2 : Green
    - 3 : Yellow (default)
    - 4 : Blue
    - 5 : Magenta
    - 6 : Cyan
    - 7 : White
	- Examples:
		- `![000/C3다빛솔루션!]` : shows "다빛솔루션" («Dabit Solution») in yellow
		- `![000/C1빨강/C2녹색/C3노랑/C4파랑!]` : applies a different color to each word («red», «green», «yellow», «blue»)

> [!info] Official firmware V4.5.4 or later — 36 colors and direct color values (all models)
> - One character after `/C` or `/G` selects one of **36 colors**: `0`~`9` · `A`~`Z` (lowercase letters give the same colors). `0`~`7` are the same as the 8 colors above. If you use a character that is not in the table (`@`, `-`, and so on), the whole message is rejected (F). Two-digit numbers (`/C12`) do not work — the `2` after `1` is shown as a character
> - **Direct value**: `/C#RRGGBB` · `/G#RRGGBB` (6 hexadecimal digits). Examples: `![000/C#FF8000주황 글자!]` («orange text»), `![000/C#FFFFFF/G#004080흰 글자 남색 칸!]` («white text, navy cell»). This applies only to ASCII text (HEX protocol text is read as the 36 colors)
> - Firmware V4.0.3 or earlier accepts only the 8 colors above (`0`~`7`). For the `/K` 64 colors of versions V4.1.3 to V4.4.0, see [[2.9.3. 64-Color Text (K Attribute)]]

#### 2.2.10. /Gx
- x: text background color setting
    - 0 : Black (default)
    - 1 : Red
    - 2 : Green
    - 3 : Yellow
    - 4 : Blue
    - 5 : Magenta
    - 6 : Cyan
    - 7 : White
	- Examples:
	    - `![000/G1다빛솔루션!]` : shows the text `다빛솔루션` («Dabit Solution») on a red background
- From the official V4.5.4, `/G` also accepts the 36 color characters (`0`~`9` · `A`~`Z`) and `/G#RRGGBB` — see the 36-color table in the /Cx section above. `/G` is the background color of the character cells, not the background of the whole screen


#### 2.2.11. /Tx
- Set up to 4 font groups to apply Latin, Korean, and user fonts separately
- x: select the font group to use
    - `0` : Font group 1 (default)
    - `1` : Font group 2
    - `2` : Font group 3
    - `3` : Font group 4
    - `폰트 그룹 N` (Font group N) on the DabitOne font transfer screen = `/T(N-1)` (counted from 0)
	- Examples:
	    - `![000/T1다빛솔루션!]`: shows the text `다빛솔루션` («Dabit Solution») with font group 2
- To use two or more font groups on one screen, divide the screen into sections (`/Pxxyy`, `/Xxxyy`, `/Yxxyy`) and set the font group for each section
- You must send the fonts before you use them - [2.4.1. Changing Fonts](https://docs.dabitsol.com/2.4.1) (Korean)

#### 2.2.12. /ixx
- xx: shows various information text, such as date, time, temperature/humidity, and fine dust level
- For details, see [[3.27. How to Display Information Text]]
- Example 1: year-month-day
	- `![000/i17-/i18-/i19!]`: 25-01-21 
- Example 2: hour:minute:second
	- `![000/i20:/i22:/i23!]`: 13:56:29  

#### 2.2.13. Default display attribute values (Default Display Properties)
- If you send default display attribute values, they apply when you send text, even if you do not set all the attributes
- Default display attribute packet: `![0032` + the attributes to set + `!]`
- Include in the packet only the attributes that you need to change
- Examples:
    - `![0032/P0000/D9901/F0003/E0101/S2002/X0000/Y0000/B000/C3/G0/T0!]`
    - `![000다빛솔루션!]`
    - `![000/P0001/Y0400/S0000/C7환영합니다!]`
        - ![[ascii_1.png]]
#### 2.2.14. Notes
- To use `/` (slash) in the text, enter `//`
	- Example: `![000/C7A//S문의!]` -> A/S문의 («A/S inquiry»)

## 3. Special command protocol structure

- List of special command codes that DABIT controllers use to set and control the LED display
- To simulate a command, enter it in the `ASCII 프로토콜` (ASCII protocol) input box at the bottom of the DabitOne `전송` (Send) tab, then click `ASCII 전송` (ASCII send) (legacy: enter it in the **"ASCII 메시지"** (ASCII message) section of the DABIT Protocol Simulator (DBPS))
- After you send a command, **always check the response packet** before you send the next command
- If there is no response or the response is abnormal, **error handling (resend, communication reset, and so on)** is necessary
