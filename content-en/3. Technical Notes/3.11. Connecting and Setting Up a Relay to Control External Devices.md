> [!abstract] How to connect a 2-channel relay to the controller and control external devices directly

#### Overall connection diagram
- ![[2relay_1.png|500]]
#### Controller - 2 Relay Module connection

| Controller J4 Relay | 2 Relay Module |
| ------------- | -------------- |
| GND           | GND            |
| D1            | IN2            |
| D2            | IN1            |
| 5V            | VCC            |

#### 2 Relay Module - external device connection
- COM (Common): the common terminal. It connects to NO or NC and is used as the input terminal of the electric circuit
- NO (Normally Open): the circuit is usually open. When the relay is active, the circuit closes and the device turns on
- NC (Normally Closed): the circuit is usually closed. When the relay is active, the circuit opens and the device turns off
- If you use the relay with 220V and the back electromotive force (back EMF) causes a controller malfunction or noise on the LEDs, we recommend that you install a spark killer
	- Install the spark killer on the same ports that connect the external device to the relay
	- Example: if the external device is connected to the COM and NO ports of the relay, connect the spark killer to the COM and NO ports too

#### How to test after the connection

##### Setting path
- DabitOne: `고급` (Advanced) > `릴레이 신호` (Relay signal)
- DBPS: `Setting` > `Additional Function` > `Relay signal`

##### Relay signal dialog (controls 2 channels)
- `None`: keeps the current setting
- `On`: activates the relay
- `Off`: deactivates the relay
- `숫자` (Number): activates the relay for the number x100ms
- `전송` (Send)

#### Relay control packet (ASCII protocol)

**Frame structure:** `![0022{Relay1}{Relay2}!]`

- Boards with V3.6.0 or later get the new `![00P2{Relay1}{Relay2}!]` packet first. Only old boards fall back to `![0022{Relay1}{Relay2}!]` (the control value encoding is the same)

| Field | Length | Description |
| ---- | ---- | ---- |
| `0022` | 4 digits | Relay control OPCode |
| Relay1 | 5 digits | Control value of relay 1 |
| Relay2 | 5 digits | Control value of relay 2 |

**Relay control value encoding:**

| Selection | Sent value | Meaning |
| ---- | ------- | ---- |
| None | `61696` | Keeps the current setting (no change) |
| On | `61440` | Relay always active |
| Off | `00000` | Relay inactive |
| 1~230 | `00001`~`00230` | Active for the value × 100ms, then inactive automatically |

**Examples:**

| Purpose | Packet |
| ---- | ---- |
| Relay1=On, Relay2=Off | `![00226144000000!]` |
| Relay1=Off, Relay2=On | `![00220000061440!]` |
| Relay1=active for 5 seconds (50 × 100ms), Relay2=keep | `![00220005061696!]` |
| Both channels On | `![00226144061440!]` |
| Both channels Off | `![00220000000000!]` |

> [!info] For multiple RS485 connections
> If an RS485 address is set, the first `0` of the 4-digit OPCode is replaced with the RS485 address (HEX).
> Example: address 5 → `![5022{Relay1}{Relay2}!]`
