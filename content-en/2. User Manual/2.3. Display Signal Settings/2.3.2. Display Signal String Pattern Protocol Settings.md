title: 2.3.2. Display Signal String Pattern Protocol Settings
---

> [!abstract] What each part of the Dabit Solution display signal string pattern protocol means, and how to set it


### Basics
#### Check the module and the controller version
- Check whether the drive IC of the module is supported by the Dabit Solution controller
- Controller V3.8.3 or later: set it with the `H2` command (this document)
- Controller earlier than V3.8.3: use the old command `0044` — [[#Older firmware (earlier than V3.8.3)]]
#### Basic structure of the setting packet
- Write: `![00H2<header>_<pattern>!]`
	- Put the pattern string (it starts with `S`) right after `H2`, **with no space**
	- If you put a space, it is rejected with an error (`F5`)
	- Header format: `SnnDnTnCnInWnnPn`
	- Pattern format: see [[#Pattern examples]]
- Read: `![00H2!]` — checks the current pattern
- Response: `![00H2 <header>_<pattern>!]` — returns the applied value as it is (1 space after `H2`)
#### String size limits
- Whole pattern string (header + pattern): up to **49 bytes**
- Groups (separated by underscores): up to 2
- Segments per group: up to 6
- Row letters per segment: up to 2
- If you go over a limit, the controller cuts off the end with no warning, so it does not work as intended
#### How to set it
- Write the display signal setting packet yourself, with the steps below
- Or enter only the pattern string in the display signal input window of DabitOne — [[#Entering it in DabitOne]]
- Or download the display signal setting program from [[Software Downloads]] and make the packet

> [!note] If you use DabitChe
> DabitChe can also choose a display signal from the built-in list and send it — `환경설정` (Preferences) > `표출신호 설정` (Display signal settings) (see [[2.3.1. Display Signal Settings]]). This list covers most Dabit Solution modules.
>
> However, **DabitChe cannot make and enter a pattern string yourself**, as this document does. If you must use a module that is not in the list, use DabitOne, or download the display signal setting program from [[Software Downloads]] and make the packet.

### Setting steps

#### 1. Send the basic display signal
```
![00H2S16D1T1C0I0W16P0_a16!]
```


#### 2. Send the screen size
- Even for modules with 2 or more rows, send 1 row × 4 columns. After you send the pattern scan (![0046!]), look at the pattern and adjust the columns
	- 1 row × 2 columns: `![004001020!]`
	- 1 row × 4 columns: `![004001040!]` (Default)
	- 1 row × 6 columns: `![004001060!]`
	- 1 row × 8 columns: `![004001080!]`
	- 1 row × 12 columns: `![004001120!]`

#### 3. Send the pattern scan 
```
![0046!]
```
- A normal pattern shows only one pixel at a time
- When the pattern looks wrong - [[#Pattern exceptions]]
	- Two pixels show side by side
		1. Change the decoder IC (`Tn`)
		2. Send the basic display signal
	- The pattern shows after a delay
		1. Send the screen size with fewer columns
		2. Send the pattern scan
	- Patterns show at the same time, offset
		1. Send the screen size with more columns
		2. Send the pattern scan

#### 4. Enter the pattern
- Pattern letters + repeat
- Pattern letters
	- Use only lowercase letters, digits, and underscores (`_`) (only the repeat mark `X` is uppercase)
	- Row (lowercase) - a = row 1, b = row 2, ... , q = row 17 — use only the lowercase row letters `a`~`q`
	- Column (digit) - 1 = column 1, 2 = column 2, ...
	- Underscore (`_`)
		- Reverse direction
		- Group separator
- Repeat
	- Write a number after the uppercase X to show a repeat
	- Shows a repeat within 16x16 pixels
- [[#Pattern examples]]

#### 5. Enter the header

`SnnDnTnCnInWnnPn`

- `Snn`: scan type (1, 2, 4, 8, 16, 32), default: S16
- `Dn`: data lines (1, 2), default: D1
- `Tn`: decoder IC type (0~4), default: T1
- `Cn`: Color Order (0~7), default: C0
- `In`: drive IC type, default: I0
- `Wnn`: number of pixels controlled at the same time in one scan
	- sum of the numbers in the pattern × repeat value
	- Examples
		- i64a64 = W128
		- a_8e8X2 = W32
- `Pn`: module identifier, optional
	- P0: standard HUB75 (default if omitted)
	- P1~P9: non-standard, set if needed

#### 6. Send the packet
`![00H2<header>_<pattern>!]` — no space between `H2` and the pattern string

#### Entering it in DabitOne
- Open the input window with `설정` (Settings) > `표출신호 설정` (Display signal settings) > `표출신호 입력` (Enter display signal) button
- Enter the pattern string (example: `S16D1T1C0I0W16P0_a16`) and click `전송` (Send) or `등록 후 전송` (Register and send)
- Registered codes stay in the list for reuse (they stay after you restart the program)
- If a rule is broken (more than 49 bytes, uppercase row letters, and so on), a warning shows — you can still send after the warning, but the controller can cut the string off or ignore it
- The program builds the packet (`![00H2...!]`), so you enter only the pattern string — see [[2.3.1. Display Signal Settings]]
- If the list is long and hard to search, use the `표출신호 필터` (Display signal filter) button to narrow it down by the conditions that you know, such as duty, data lines, drive method, and driver IC (V4.6.0 or later) — see [7.7. Display Signal Filter](https://docs.dabitsol.com/7.7) (Korean)


#### Header parameters in detail

| Parameter    | Meaning                | Range                   | Example  | Description                                      |     |
| ------- | ----------------- | ---------------------- | --- | --------------------------------------- | --- |
| **Snn** | Scan ratio (1/nn scan)   | 01, 02, 04, 08, 16, 32 | S16 | 1/16 scan                              |     |
| **Dn**  | Number of data lines          | 1, 2                   | D1  | D1: single data line<br>D2: dual data lines            |     |
| **Tn**  | Decoder IC type         | 0–4                    | T1  | Selects the decoder IC type (see the T parameter table below)            |     |
| **Cn**  | RGB color order         | 0–7                    | C0  | Selects the color order (see the C parameter table below). C0 = not set = RGB   |     |
| **In**  | Driver IC type        | 0–9                    | I0  | Selects the driver IC type (see the I parameter table below)          |     |
| **Wnn** | Pixels controlled per data line | 16–128                 | W32 | Number of pixels controlled in 1 scan                          |     |
| **Pn**  | Non-standard module identifier        | 0–9 (optional)               | P0  | P0: standard HUB75. P1~P9: modules with a completely different scan method/connector |     |

#### T parameter details (decoder IC type)

| Value   | IC type               | Use cases                   |
| --- | ------------------- | ----------------------- |
| T0  | No decoder IC           | 1/4 duty and 1/2 duty      |
| T1  | 74HC138, forward         | Common decoder IC             |
| T2  | 74HC138, reverse         | VISSEM 3Color 1/16 duty |
| T3  | 74HC595 (SUM2017TD) | 1/8 duty             |
| T4  | L800                | 1/4 duty             |

#### C parameter details (Color Order)

The C value follows the order of the `Color Order` combo in the program (RGB=C1 … BGR=C6). **C0 means not set**, and works the same as C1 (RGB).

| Value   | Color Order | Color order on screen (when R·G·B signals are sent) |
| --- | ----------- | ------------------------------ |
| C0  | Not set (= RGB) | Red · Green · Blue                 |
| C1  | RGB         | Red · Green · Blue                 |
| C2  | RBG         | Red · Blue · Green                 |
| C3  | GRB         | Green · Red · Blue                 |
| C4  | GBR         | Blue · Red · Green                 |
| C5  | BRG         | Green · Blue · Red                 |
| C6  | BGR         | Blue · Green · Red                 |
| C7  | Reserved         | –                              |

> [!tip] When the module shows the wrong colors
> For example, if red text shows as blue, the color order does not match. Change `Color Order` and send again until red, green, and blue show in the right places. When you write the display signal string yourself, put the C value from the table above in the header.

#### I parameter details (driver IC type)

Driver ICs are divided into three groups by **drive method**. A different method changes the brightness and the transfer behavior, so check the IC on the module before you choose.

| Value   | Drive method | Driver IC        | Note                                   |
| --- | ------ | -------------- | ------------------------------------ |
| I0  | BCM    | Standard (general)        | Most HUB75 modules. ICN2037BP·FM6124DJ·MBI5120GM·SM16208, and others |
| I1  | BCM    | FM6126A        |                                      |
| I2  | BCM    | FM6124         |                                      |
| I3  | BCM    | ICN2038S       |                                      |
| I4  | BCM    | MBI5153        |                                      |
| I5  | BCM    | MBI5042        |                                      |
| I6  | BCM    | ICN2053        |                                      |
| I7  | S-PWM  | SM16380SA      | Shows on DB720 (official V4.5.4 · 128×64 · 1/32 scan). After the transfer, the LED display restarts by itself (normal). Lights up after power-on with no command |
| I8  | S-PWM  | IT1504         | After the transfer, the LED display restarts by itself (normal)             |
| I9  | EPWM   | FM6363C        | A 3rd method, different from BCM and S-PWM. After the transfer, the LED display restarts by itself (normal)<br>Brightness is set by the drive current |
| I10 | S-PWM  | ICND1065L      | Shows on DB720 (official V4.5.4 · 128×64 · 1/32 scan). Pure black background · no ghosting · brightness control · move left |

> [!note] When the screen goes off for a moment after the transfer
> With I7 · I8 · I9 modules, the LED display restarts by itself when it receives the display signal. A blank screen for a few seconds is normal, and the content shows soon.

## Pattern examples
#### Basics
- A normal pattern shows only one pixel at a time
- The pattern moves by columns along each row
#### Forward movement
- The basic pattern: in row `a`, 16 pixels light up in one pass, in order **from left to right (1→16)**
- Write forward movement **with no underscore (`_`)**, in the form `(row letter)(number of columns)`
- a16
- ![[패턴_정방향.png|500]]

#### Reverse movement
- In row `a`, 16 pixels light up in order **from right to left (16→1)**
- For reverse movement, put **an underscore after the row letter**, in the form `(row letter)_(number of columns)`
- a_16
- ![[패턴_역방향.png|500]]
#### Moving in pairs
- **Combine two or more row letters**, and those rows **work in turn**
- Syntax: `(row letter)(row letter)(number of columns)`
	- For reverse movement, put `_` after the row letters
- ac16
- ![[패턴_쌍이동.png|500]]
- ia_16
- ![[패턴_쌍이동역방향.png|500]]
#### Repeat (minimum unit 16x16)
- `Xn` **repeats** the same form **n times**
- Write it based on the minimum unit of **16×16 pixels**
- a_8e8X2
	- 8 pixels in reverse on row `a` + 8 pixels forward on row `e`, **repeated 2 times**
	- ![[패턴_반복x2.png|500]]
- ac_4eg4X4
	- 4 pixels on rows `a,c` + 4 pixels on rows `e,g`, **repeated 4 times**
	- ![[패턴_반복x4.png|500]]
#### Writing a pattern based on 16x16 pixels
- If the pattern repeats 2 times per 16x16 pixels on a 1 row × 2 columns (16x32 pixels) module, write only the 16x16-pixel pattern
- i16a16![[패턴_16x16_1.png]]
- i32a32![[패턴_16x16_2.png]]

#### Pattern exceptions
- Two pixels show side by side at the same time - select T0 (No decoder IC)
- ![[패턴_예외1.png|500]]
- Patterns show at the same time, offset -> send the screen size with more columns > send the pattern scan
- ![[패턴_예외2.png|500]]


### Older firmware (earlier than V3.8.3)
- Firmware from V3.2.8 to earlier than V3.8.3 uses the numeric command `0044` instead of `H2`
- Write: `![0044 <header>_<pattern>!]` — **1 space** after `0044` (different from H2)
- Read: `![0045!]`
- The rules for the pattern string (header and pattern syntax) are the same as for H2
