---
title: 2.9.3. 64-Color Text (K Attribute)
---

> [!abstract] The `/K` attribute, which extends the text color from the existing 8 colors to 64 colors — syntax, full palette, and limits (only for versions V4.1.3 to V4.4.0 · not in the official V4.5.4)
> It combines red, green, and blue in 4 levels each, so you can use intermediate colors such as orange, pink, and gray directly in the text.

> [!warning] `/K` was used only in versions V4.1.3 to V4.4.0 — check the firmware version first
> - **V4.5.4 or later (official)**: there is no `/K` (removed from V4.4.1). To set colors, use the **36 colors** of `/C` and `/G` (`0` to `9` · `A` to `Z`), or set them directly with **`/C#RRGGBB` · `/G#RRGGBB`** — see [[2.8.1. ASCII Protocol Manual]]
> - **V4.1.3 to V4.4.0** (versions delivered individually): use the `/K` 64-color table in this document as it is — operation checked on V4.1.3
> - **V4.0.3 or earlier** (legacy protocol firmware): `/K` support is not confirmed. Use the 8 colors of `/C` and `/G`
> 
> Boards that are not upgraded to V4.5.4 accept only the 8 colors of `/C` and `/G`. You can also upgrade DB400 and DB402 boards that shipped earlier to V4.5.4 (256 colors) with the `_legacy_v1` · `_legacy_v2` files — [[2.10.1. Reading Firmware Information and Uploading Firmware]]. First check the version with `![0081!]` — see [[3.21. Reading Controller Firmware Information]]. Integrators who use the protocol simulator or send ASCII directly must be especially careful.

## 1. Syntax

`/Knn` — nn is the color number from `00` to `63` (always 2 digits)

```
color number = blue×16 + green×4 + red   (each channel: level 0~3)
```

- Channel levels 0·1·2·3 mean brightness 0%·33%·67%·100% (RGB values 0·85·170·255)
- You can express all 8 colors of the existing `/C` with `/K` — black `/K00`, red `/K03`, green `/K12`, yellow `/K15`, blue `/K48`, magenta `/K51`, cyan `/K60`, white `/K63`

### Example

```
![000/K03가/K12나/K48다/K63라!]
```

The display shows '가' in red, '나' in green, '다' in blue, and '라' in white. You can change the color anywhere in the text.

## 3. Limits

> [!warning] Use only one color system in one message
> If you mix `/K` with `/C` · `/G` in one message, a `/C` after `/K` shows **a different color than you intended**. For a message with extended colors, we recommend `/K` for the whole message — you can also express all 8 existing colors with `/K`.

- You cannot set the text background color (it is always black) — you cannot use `/G` together with `/K`
- A 16-bit color (16C) controller shows all the colors. An 8-color (08C) controller reduces them to the nearest of 8 colors
- Firmware: operation checked on **V4.1.3** — the displayed colors were checked with a camera on DIBD720U (16C; DB720U board) (2026-08-14). Command acceptance was also checked on DIBD500S·600T (08C; DB500S · DB600T boards) (2026-08-15)
- The color selection screen of DabitOne does not have this attribute yet — use it by sending ASCII directly
- From DabitOne V4.5.1, the preview and the 전광판 화면 (LED display screen) show /K colors as the actual colors (checked 2026-08-16)
- **`/K` was removed in controller firmware V4.4.1 (official version V4.5.4).** In those versions or later, use the 36 colors of `/C` and `/G` (`0` to `9` · `A` to `Z`) or `/C#RRGGBB` · `/G#RRGGBB` — [[2.8.1. ASCII Protocol Manual]]. The `/K` tables in this document are for **V4.1.3 to V4.4.0** (support for V4.0.3 or earlier is not confirmed)

> [!tip] When the colors differ from the palette table
> The cause may not be the `/K` value. The **Color Order** in the display signal settings may not match the module. First, use «When colors appear different — matching the Color Order» in [[2.3.1. Display Signal Settings]] to check that red, green, and blue appear in the right places.
